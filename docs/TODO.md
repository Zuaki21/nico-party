# 今後やりたいこと

## セキュリティ: Discord でログインした人だけが使えるようにする（2026-10-26 見送り）

### 現状の問題
- ニコニコの中継（`/nico/...`）は誰でも呼べる。中継先はニコニコの決まったドメインに限定しているので、任意のサイトへの攻撃には使えない。ただし大量に呼ばれると Cloudflare の無料枠を使い切られ、その日はアプリが使えなくなる（課金はされない）
- Discord のプロキシ（`<アプリID>.discordsays.com/.proxy/...`）は Discord の外からでも使える（`curl` で確認済み）。そのため「Discord のプロキシ経由のリクエストだけ通す」判定は効果がない
- WebSocket の `join` で送られてくる名前を検証していない。細工したクライアントなら別の名前を名乗れる（部屋 ID は推測困難なので、他人の部屋に入られる心配は小さい）

### 対策案: 署名付きの「通行証」
1. `/api/token` でトークンを交換した後、サーバーが Discord のユーザー ID と名前、期限（数時間）を入れた HMAC 署名付きの通行証を発行する
2. 中継の書き換え（`server/src/nico.ts` の `rewriter`）で、`/nico/...` の URL をすべて `/nico/<通行証>/...` にする。iframe の最初の URL（`client/src/app.ts`）にも通行証を付ける
3. 通行証がない、署名が合わない、期限切れのリクエストは拒否する
4. WebSocket の接続にも通行証を必須にし、名前は通行証の中身（本物の Discord の名前）を使う
5. 通行証ごとにレート制限（中継の回数、キューへの追加の回数）をかける

### 注意
- 自分の Discord アカウントでログインして通行証を抜き出す悪用は防げないので、5 のレート制限で抑える
- 中継の書き換えルールを変えるので、Discord 上での再生確認がもう一度必要
